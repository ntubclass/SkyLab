# 練習型機器範本設計：n8n、Database 等預設環境

- 文件狀態：設計草案
- 建立時間：2026-07-29 21:42:49（UTC+08:00，Asia/Taipei）
- 最後修訂：2026-07-29 21:57:23（UTC+08:00，Asia/Taipei）
- 適用範圍：機器範本管理、課程環境、班級建機

## 1. 核心定位

平台原本就有預先準備完成、專門提供學生使用的預設母機。學生需要環境時，系統直接從已就緒的 PVE 母機範本快速複製 VM/LXC、配置學生資料並開機，不需要等待作業系統或應用程式重新安裝。

本次增加 n8n、Database 等練習用途，不是取代原本的母機機制，也不是建立另一套部署流程；而是替既有母機範本增加「練習用途、預設範本、連接埠建議及健康檢查」等資訊。

這也不是在每位學生建機後，再透過網路下載 community script 或安裝腳本建立 n8n、Database。n8n 或 Database 應預先安裝在母機中，學生端取得的是已完成設定並可立即開機使用的 VM/LXC 副本。

此處的「實際複製」是指建立真正存在於 PVE 上的學生 VM/LXC 執行個體，不是複製實體伺服器硬體。

```text
歷史上的網路腳本方式
建立空白 VM/LXC
  ↓
從網路下載安裝腳本
  ↓
安裝 n8n／Database
  ↓
交付學生

目前平台原有的快速建機方式
管理員預先維護學生用預設母機
  ↓
預先安裝並確認 n8n／Database 可以正常運作
  ↓
保存成可重複使用的 PVE VM/LXC 範本
  ↓
教師在課程中選擇範本
  ↓
依每位學生快速複製 VM/LXC
  ↓
配置專屬 IP、主機名稱、資源與防火牆
  ↓
立即開機並交付學生
```

## 2. 現有複製邏輯

平台已具有學生用預設母機及快速複製能力。建立新的母機範本時，可以選擇一台已完成設定的 VM/LXC，系統停止該機器後將它轉換成 PVE 範本。

平常上課不會重複建立母機；教師只需要在課程環境選擇既有範本。學生建機時：

1. 優先使用 Linked Clone，以縮短建機時間及降低儲存空間占用。
2. Linked Clone 不可用或執行失敗時，自動改用 Full Clone。
3. 複製完成後，設定學生專屬的主機名稱、CPU、RAM、磁碟、IP 及防火牆。
4. 設定完成後立即開機，讓學生直接進入已準備好的練習環境。

因此，n8n 或 Database 的程式、套件與基礎設定應預先存在於預設母機，不應在全班建機時重複從網路安裝。這可以避免外部網站失效、下載速度不一致或同時安裝造成的容量尖峰。

## 3. 功能目標

管理員或教師可以替既有或新建立的母機範本標示練習用途，例如：

- 一般 Linux
- n8n
- Database

系統可以為某一種用途指定預設母機範本。教師在課程環境新增節點時，系統優先選取該用途的預設範本，達到快速建立、立即開機的效果，但仍允許教師改選其他範本。

VM/LXC 是機器類型；n8n、Database 是練習用途，兩者不可混在同一個欄位。

## 4. 建議的範本欄位

第一版建議只增加必要欄位，避免建立範本畫面過於複雜。

| 欄位 | 說明 |
|---|---|
| `practice_type` | 練習用途：`general`、`n8n`、`database` |
| `practice_variant` | 用途細分；資料庫可填 `mysql`、`mariadb`、`postgresql` |
| `is_practice_default` | 是否為該用途的預設範本 |
| `default_cores` | 預設 CPU |
| `default_memory` | 預設 RAM，單位 MB |
| `default_disk` | 預設磁碟，單位 GB |

連接埠與健康檢查可以先由系統依練習用途提供建議，不必讓使用者填寫複雜設定。

## 5. 建議的預設值

| 練習用途 | 建議規格 | 建議服務埠 | 建議檢查 |
|---|---:|---|---|
| 一般 Linux | 1 CPU／1 GB RAM／10 GB Disk | 無 | SSH 或開機狀態 |
| n8n | 2 CPU／2 GB RAM／20 GB Disk | TCP 5678 | n8n HTTP 服務 |
| MySQL／MariaDB | 2 CPU／2 GB RAM／20 GB Disk | TCP 3306 | Database 服務狀態 |
| PostgreSQL | 2 CPU／2 GB RAM／20 GB Disk | TCP 5432 | PostgreSQL 服務狀態 |

以上是系統建議值，建立範本的人仍可調整 CPU、RAM 與磁碟。

## 6. 建立範本畫面

```text
來源機器
VMID：[120                     ]

範本名稱
[n8n 練習環境                 ]

練習用途
[n8n                       ▼]

預設規格
CPU [2]　RAM [2048 MB]　Disk [20 GB]

可見性
(●) 私人
( ) 全部可見

[✓] 設為 n8n 預設範本

[建立並轉換成範本]
```

當選擇「Database」時，才顯示資料庫類型：

```text
練習用途：[Database ▼]
資料庫類型：[PostgreSQL ▼]
```

## 7. 課程環境使用方式

教師在課程環境新增節點時維持兩種來源：

```text
新增機器
├─ 選擇既有範本
│  ├─ 一般 Linux
│  ├─ n8n（預設）
│  ├─ MySQL
│  └─ PostgreSQL（預設）
└─ 新增 VM/LXC 規格
```

選擇練習用途後：

1. 系統優先帶入該用途的預設範本。
2. 自動帶入範本的 CPU、RAM 與磁碟。
3. 自動建議節點角色，例如 `n8n` 或 `database`。
4. 教師仍可更換其他範本。
5. 教師最終確認並鎖定後，課程版本不得直接修改；需要調整時建立新版本。

## 8. 與網路拓撲及防火牆的關係

練習用途只提供連線建議，不應直接開放防火牆。

例如 n8n 連接 PostgreSQL：

```text
[n8n 節點]
    │ TCP 5432
    ▼
[PostgreSQL 節點]
```

系統可以因為目標節點是 PostgreSQL，自動建議 TCP 5432；但教師仍必須確認連線方向、協定與連接埠。

同樣地，n8n 的 TCP 5678 只有在需要讓其他節點或使用者存取時才建立規則，不應因為選擇 n8n 範本就自動對所有網路開放。

## 9. 預設範本規則

- 同一個練習用途及同一個機器類型，只能有一個有效預設範本。
- VM 與 LXC 可以各自擁有預設範本。
- 「全部可見」範本可以成為全系統預設。
- 「私人」範本只能成為擁有者自己的預設。
- 將新範本設為預設時，系統應自動取消相同範圍內舊範本的預設狀態。
- 預設範本若不是 `ready` 狀態、PVE 範本已不存在或被刪除，系統不得選用。

## 10. 安全與資料隔離

- 不在範本 metadata 內儲存學生共用的明文密碼。
- 不把母機中的固定 SSH 私鑰複製給所有學生。
- 學生專屬 IP、SSH 金鑰及必要密碼應在複製後產生或注入。
- Database 預設只允許課程拓撲內指定節點連線。
- n8n 的管理介面不可預設對整個外部網路開放。
- 母機轉成 PVE 範本後不能再當一般 VM/LXC 使用；更新範本時應先 Full Clone 出可編輯副本，修改完成後再轉回範本。

## 11. 建議實作順序

### 第一階段：練習用途分類

1. 增加 `practice_type`、`practice_variant`。
2. 建立範本表單增加練習用途選項。
3. 範本列表顯示「n8n」「PostgreSQL」等標籤。
4. 課程環境選擇範本時可以依用途篩選。

### 第二階段：預設範本

1. 增加 `is_practice_default`。
2. 實作全部可見與私人範本的預設範圍。
3. 課程新增節點時自動帶入預設範本。

### 第三階段：連線與健康檢查建議

1. n8n 自動建議 TCP 5678。
2. MySQL／MariaDB 自動建議 TCP 3306。
3. PostgreSQL 自動建議 TCP 5432。
4. 建機完成後執行對應服務健康檢查。

## 12. 驗收條件

- 可以直接替原有的學生用預設母機設定 n8n、Database 等練習用途，不必重新製作或重新轉換範本。
- 可以從一台已安裝 n8n 的 VM/LXC 建立 n8n 練習範本。
- 建立範本時不需要重新下載 n8n 安裝腳本。
- 可以從已安裝 MySQL、MariaDB 或 PostgreSQL 的母機建立 Database 範本。
- 課程環境可以依練習用途找到範本。
- 新增 n8n 或 Database 節點時可以自動帶入預設範本與資源規格。
- 每位學生取得獨立的 VM/LXC、IP 與存取憑證。
- Linked Clone 失敗時可以安全改用 Full Clone。
- 複製及個人化設定完成後會立即開機，不需要等待應用程式重新安裝。
- 系統只建議服務連接埠，不會未經教師確認就開放防火牆。
- 教師鎖定課程版本後，範本及拓撲不會被直接修改。

## 13. 與原有快速模板規則的關係

同一個預設母機範本可以被不同流程使用，但生命週期必須由使用入口決定，不能全部套用固定 3 小時。

| 使用入口 | 主要使用者 | 建立方式 | 使用期限 |
|---|---|---|---|
| 學生快速模板 | 學生自行開啟短期練習環境 | 容量足夠時自動核准並立即建立 | 固定 3 小時 |
| 課程環境／班級建機 | 教師替每位學生配置正式上課環境 | 教師鎖定、容量預檢及管理員審核後建立 | 依班級上課時間與生命週期 |

### 13.1 學生快速模板既有規則

學生從「快速模板」入口選擇 n8n、PostgreSQL 等服務環境時，必須保留原有規則：

- 僅支援 LXC。
- 必須使用允許的服務模板。
- 有可用容量時自動核准並立即建立。
- 前端不提供開始與結束時間欄位。
- 後端固定覆寫使用區間：

```text
start_at = now
end_at = now + 3 hours
```

- 容量檢查範圍為現在到 3 小時後。
- 使用時間固定 3 小時，學生不能自行延長。
- 到期後由 scheduler 自動進入關機流程。
- 禁止 GPU。
- CPU 最多 2 cores。
- RAM 最多 4096 MB。
- Disk 最多 32 GB。
- 每位使用者同時最多 1 個快速模板。
- 每位使用者 24 小時內最多建立 3 個快速模板。
- 只使用目前剩餘容量，不為快速模板重排其他研究申請或既有資源。
- 正常情況不主動搬移已建立的快速模板。

### 13.2 目前服務白名單

目前快速模板允許的服務為：

- PostgreSQL
- MongoDB
- Grafana
- Homepage
- WordPress

n8n 目前不在既有白名單中。若希望學生能從快速模板入口直接開啟 n8n，實作時除了替母機增加 `practice_type = n8n`，還必須將 `n8n` 加入後端服務白名單。

「Database」是範本分類，不應直接當成快速模板服務代號。快速模板應使用明確服務名稱，例如 `postgresql`、`mysql` 或 `mariadb`，才能正確決定連接埠、檢查方式與資源限制。MySQL、MariaDB 若要提供，也需要另外加入白名單。

### 13.3 課程環境不固定為 3 小時

教師在課程環境中選擇同一個 n8n 或 Database 母機時，不套用快速模板的固定 3 小時限制。

課程環境依照以下資料管理生命週期：

- 班級開始與結束日期。
- 每週上課時段。
- 單次上課持續時間。
- 教師最終確認與鎖定狀態。
- 管理員審核結果。

因此必須由申請來源標示用途，例如：

```text
quick_template → 固定 3 小時
course         → 使用班級與課表生命週期
```

這樣同一個預設母機可以同時服務短期快速練習與正式課程，但不會混用時間、審核及容量規則。

## 14. 結論

平台原本就有提供學生使用的預設母機與快速複製機制。本次功能只需要讓這些既有母機可以標記為 n8n、Database 等練習用途，並指定各用途的預設母機，不需要改變原本的建機架構。

練習用途欄位負責分類、預設範本、資源建議、服務埠建議及健康檢查；實際學生環境仍由已就緒的 PVE 母機範本進行 Linked Clone，必要時改用 Full Clone。完成學生專屬設定後立即開機，因此不依賴建機當下的外部網路安裝，也能維持全班環境一致。
